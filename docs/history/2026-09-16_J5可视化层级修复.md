# J5 可视化层级修复

根因是生成 `models/dummy_studio_visual.xml` 时把零件名称误当成所属运动关节：`dummy_j5` 实际是长前臂及 J5 驱动的固定侧，不能放到 J5 输出节点。此前 `robot_hierarchy.json` 还把 j5_anchor 导出成 Label 并形成循环，不能作为正确装配树。

从已验证能运行的 DummyStudio 副本 `DummyStudio_Data/level0` 重新读取原始 Transform，并读取 `DummyRobotBridge` 的 jointBodys 绑定以及 Update 的旋转赋值。绑定依次是 135、149、136、138、148、133；对应 j1_anchor、j2_j3_anchor、j4_anchor、j5_anchor、j6_anchor、end_anchor。名称编号不等于实机的关节编号。

已修复：

- 长前臂 `dummy_j5`、其电机和护盖归属 J4。
- 末端短腕 `dummy_j6`、其电机和护盖归属 J5。
- `dummy_j4_cover` 与对应结构件、电机一起归属 J3，避免壳体被另一个轴带走。
- 按 Studio 的坐标变换修正 J4/J6 方向，J6 轴位置从猜测的 y=−178 mm 改为场景的 y=−222 mm。

原有 OBJ 三角形完整保留，重新计算各刚体局部坐标。没有改动实机控制命令、零点、电流或限位，也没有为本轮修复发送运动指令。

证据保存：`models/studio_source/studio_verified_transforms.json`、`studio_bridge_rotation_il.txt`。回归测试 `tests/test_studio_articulation.py` 独立计算原 Studio 变换，检查四组姿态下全部六轴的位置和方向、J5 上游零件不动、壳体与电机始终属于同一刚体。全套 26 项测试通过。仅 J5 正负 30° 的离线效果保存在 `outputs/j5_corrected_motion.gif`。

`六轴同时往复仿真.cmd` 与 `MuJoCo实机同步.cmd` 都加载同一修正后的 XML。已打开的窗口仍保留旧模型，需要关闭后重新启动。动力学质量、惯量和实际机械标定仍未验收。原场景的 J6 输出节点没有单独外观网格，不能把整段腕部错误归给 J6 来制造可见转动。
