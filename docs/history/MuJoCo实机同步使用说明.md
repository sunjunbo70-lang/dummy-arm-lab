# MuJoCo 实机同步上位机

## 直立复位与折叠按钮

- **直立复位**：目标 `[0,0,90,0,0,0]` 度。先将 J1/J4/J5/J6 调到 0，再将 J2 调到 0，最后 J3 调到 90。
- **折叠**：目标 `[0,-75,180,0,0,0]` 度。先将 J1/J4/J5/J6 调到 0，再将 J2 调到 −75，最后 J3 调到 180。
- 点击任一按钮会先停止正在进行的手动/自动跟随，从重新读取的当前角度接续执行；不自动恢复原来的往复模式。每阶段到位后才进入下一阶段，最后停止并保持只读同步。
- 遵循当前速度设置以及原有跟随误差/停滞检查，途中可按停止或空格取消，不自动回程。这是预设姿态运动，不是重新寻找机械零点或写入校准。
- 已测试阶段顺序、自动模式切换为复位、到位停止及取消请求；按钮的新执行流程尚未进行本轮实机完整动作验证。任意起始姿态的中间路径仍需现场观察。

## 全范围连续线性往复（更新）

- 点击“启动六轴全范围线性往复”，从当前实机角度开始，六轴各自在本界面软件上下限之间持续往返。取消小幅度、循环次数和几个目标点等待到位的旧模式。
- 每轴初始向角度增大方向运动；已在上限的轴立即向下限方向运动。按设定角速度逐次生成中间目标，到边界反向。各轴范围不同，因此换向时刻不同；不强求六轴同时到达边界。
- 运行不会因为完成一轮自动结束。停止按钮、空格、Esc 或关闭窗口会请求停止；反馈异常、停滞和界面失去响应仍会触发停止。停止后不自动返回起点。
- “跟随速度”1～20°/秒，默认5，可在运动中调整。它限制上位机关节目标变化速率，不写入固件速度、电流、加速度参数。实体换向时有加减速，不保证实际角速度严格恒定；关节角度线性变化也不等于末端沿空间直线运动。
- 右侧预览与滑块显示实际逐次下发的轨迹角度，左侧显示实机反馈。约10 Hz离散调度，不是硬实时控制；发生调度延迟不补发大步追赶。
- 仍保留2°目标领先量、3°偏差和2秒逐轴停滞检查。若反馈跟不上，轨迹暂停推进，右侧显示暂停状态；不会让虚拟目标继续走而实体滞留。
- 本模式覆盖当前软件范围：J1 −20～20°，J2 −75～20°，J3 90～180°，J4–J6 −15～15°，不扩展硬件限位。多个轴各自合法不等于组合姿态无碰撞，仍需现场监督。
- 停止或故障后保存 `outputs/live_serial_*.auto_*.json`：包括起始姿态、上下限、各轴换向计数、观测范围及反馈暂停次数。结果不冒充机械精度验收。
- 已用模拟通信和1200步轨迹测试验证所有轴能覆盖两端、持续换向、不自动结束、变速连续及手动停止。尚未执行本版全范围六轴实机扫描；窗口启动保持只读，需点击按钮开始。

更新：已按原始 DummyStudio 场景及控制代码修正 J5 零件归属、相邻关节外壳归属、J4/J6 方向和 J6 轴位置。详见 `2026-09-16_J5可视化层级修复.md`。关闭旧窗口后重开生效；下文关于未实机标定和不能凭模型判断碰撞的限制仍适用。

启动：项目根目录双击 `MuJoCo实机同步.cmd`。先关闭 DummyStudio 和其他控制程序，避免串口占用。程序需要本项目现有 `.venv-loop` 与已修复的原生 USB 接口；本次在当前 Windows 电脑验证，未在 Ubuntu 验证。

## 操作

1. 启动自动只读连接指定序列号的机械臂，读取六轴角度。两侧模型和目标滑块初始化为当前实机姿态，不自动复位、不自动展开。
2. 左侧显示原生 USB 读回的角度对应的模型；右侧显示滑块目标。未开启跟随时，拖动滑块只预览。
3. 点击“开启实时跟随”。程序丢弃先前预览目标，重新对齐当前反馈；随后拖动滑块，目标会逐步发送到实体。开启本身不执行旧预览姿态。
4. “停止跟随”、空格或 Esc：请求 STOP 并停止下发目标，继续只读显示。关闭窗口先尝试停止，再释放 USB。发生故障后需要手动重新连接，不会自动恢复运动。
5. 鼠标在模型图像上拖动仅旋转视角，滚轮缩放。控制关节请用下方滑块；不是拖拽模型施加仿真力。

## 当前范围和验证

- J1：−20～20°；J2：−75～20°；J3：90～180°；J4–J6：各 −15～15°。这是本版界面的保守调试范围，不代表已标定机械限位，也未改写控制器限位。
- 目标变化限制为每轴 1～20°/秒可调，默认 5°/秒；每次发送目标最多领先反馈 2°。约 10 Hz 读取和调度，旧目标被新目标替换，不积压轨迹。它不是硬实时控制器，设置值也不是对驱动器瞬时速度的认证保证。
- 有逐轴停滞、偏差、非法值和界面心跳检查。USB 中断后不能保证 STOP 送达，进程被强制终止时也不能保证执行退出清理。保留实体停止手段。
- 2026-09-16：实际窗口拖动 J1 完成约 0→4.96→0°；持续 ASCII 查询出现损坏回包后按设计停止。最终版本改为原生 USB 反馈，再通过窗口完成约 0→2.08→0°，最后点击停止，收到 `Stopped ok` 且只读反馈继续更新。
- 本界面已验证 J1；此前独立指令已由用户确认 J1 往返和 J2/J3 折叠实体正常。不能把这扩大为 J4–J6、任意多轴路径或碰撞安全全部验收。

## 显示与控制的边界

界面使用 MuJoCo 渲染和正运动学更新，不把未标定动力学产生的力或力矩下发给实体。控制以固件角度为准，复位角度是 `[0,0,90,0,0,0]`；显示暂用相对该复位角度的模型关节坐标。现有完整外观模型的轴、零位和装配映射仍需逐轴校准，不能用图中不碰撞证明实体路径安全。

原生接口角度加已比对的偏置 `[0,-75,180,0,0,0]` 得到固件关节角。连接时与一次 ASCII 角度读取交叉检查；原生接口失败不会退回可疑的持续 ASCII 查询。返回的是固件缓存，没有电机采样时间戳，界面“最近反馈响应”只代表电脑收到响应的时间。

控制代码：`dummy_loop/live_control.py`；界面：`tools/live_mujoco.py`；日志：`outputs/live_serial_*.jsonl` 与对应 `.feedback.jsonl`。`SerialRobot.send_action()` 的无人监督算法保护未移除。本工具是有人监督的上位机调试入口。
