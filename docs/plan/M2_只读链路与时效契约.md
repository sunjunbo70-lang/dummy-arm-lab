# M2 只读链路与时效契约

状态：未开始

目标证据级：L2
前置：M1 已合入

## 为什么这一步不能跳

现在下发走串口、读回走原生 USB，两条通道各自为政，而且读到的是固件缓存角度。
`serial_backend.py` 首行注释写明「RX age is NOT the age of each motor's feedback」，
`get_state()` 返回的 `device_freshness_known=False`。

也就是说：你知道主机在 T 时刻收到了这组数字，但不知道电机何时测出、
六轴是否同一时刻采样、固件缓存了多久。

这个问题不解决，采集的 (状态, 动作) 对是系统性错位的。训练会正常收敛、
loss 会下降、验证集看起来正常——因为验证集有同样的错位。到实机上才发现策略行为
诡异，那时已无法判断是算法、数据量还是时序问题。

## 我做什么

- 统一读取侧：`DummyArm.read()` 融合两条通道，返回带 per-source 时间戳的 `Observation`
- 新工具 `tools/hardware/record_readonly.py`：JSONL 输出，每帧含
  `host_recv_time` / `round_trip_ms` / `source` / `seq` / `raw`
- 把「不知道的东西」显式写进数据：采样时刻未知时标注延迟上界，
  不拿 `host_recv_time` 冒充采样时刻
- stale 检测：超过 `timing.max_observation_age_s` 必须报错而不是沿用旧值
- 事后分析三段录包，写 experiments 记录

## 你做什么

- 接线并确认端口
- 按指示启动三段录包
- 在第三段中途拔一次 USB

## 验收

- 三段各 ≥ 60 秒，其中一段含人为断连
- 日志可区分正常帧、坏帧、超时三种情况
- 断连点在日志中可定位到具体帧
- 断连后日志标 stale，未继续记录旧姿态
