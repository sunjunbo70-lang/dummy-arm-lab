# M3 逐轴标定

状态：未开始
会话类型：硬件会话（用户全程在场，手放急停）
目标证据级：L3
前置：M1、M2 完成

## 每轴四步，顺序 J1 → J6

1. **方向** — ±1° 点动，记录实体转向，确定 `firmware_to_canonical_sign`
2. **零位** — 对照 CAD 与折叠标记，记录 `firmware_zero_deg`
3. **软限位** — 慢速双向试探，各留 2° 余量写入 `lower_rad` / `upper_rad`
4. **速度** — 固定 `firmware_speed_parameter`，实测对应的实际角速度

另做一次独立的急停实测：运动中真按硬件急停，确认确实停住，
才能置 `physical_stop_verified`。

## 关键验证点

**首目标与实体姿态一致**是整个 M3 的要害。它检验 `sign` 和 `offset` 对不对。
符号标反时，错误的编码与错误的解码互相抵消，读数看起来完全正常——
只有人用眼睛看着机械臂往哪边转才能发现。

此后所有动作、所有采集的数据、所有训练出的策略都建立在这次对质的结果上。

## 我做什么

- 生成每轴的命令序列与执行前检查表
- 每轴开始前的只读姿态确认脚本
- 事后把测量值整理进 profile，附证据路径
- **不执行任何带 `--enable` 的命令**

## 你做什么

- 全程在场，手放急停
- 执行所有点动命令
- 用眼睛确认每次转向与到位姿态
- 急停实测并留照片或录像

## 验收

- `jog` 单轴 1° 跑通，首目标与实体一致
- 急停实测有影像证据
- 四个 `*_verified` 每一个都能指向一条实验记录
- 产出 `configs/hardware.dummy_v2.calibrated.json`

## 证据落点

`experiments/<日期>_calibration/`

## 回滚

标定值写新文件，不覆盖 `hardware.unverified.json`。
标定有疑问时改用旧 profile，门禁会重新拒绝运动，回到安全状态。
