# S2 整片抹墙 v0.6：物理一致全轨迹与重训练计划

状态：**审查草案，不执行**  
会话类型：软件会话  
目标证据级：L1  
前置版本：v0.5 P1（提交 `db5a203`）  
目标：修复装料姿态、带料搬运姿态和接触前回缩三个结构性问题，在完整轨迹通过硬门槛后重新生成数据并训练。

## 1. 决策摘要

v0.5 的主要问题不是 PPO 步数不足，而是材料状态、末端真实姿态和回放轨迹没有使用同一个状态源。
v0.6 采用以下原则：

1. 工具是否朝上只能由 MuJoCo 中的真实工具坐标系计算，策略不能直接声明 `carry_face_up`。
2. 装料、抬升、搬运、近墙旋转、接触、涂抹、离墙全部生成连续 SE(3) 轨迹并逐点求逆解。
3. 材料装载和掉落必须依赖实际接触、实际姿态和每个仿真时间步，不再由阶段名称直接改变。
4. 保料姿态与单调接近属于底层技能硬约束；高层策略只决定作业意图和可优化参数。
5. 教师全流程轨迹未通过验收时禁止开始行为克隆、DAgger 或 PPO。
6. 增加每回合操作预算，但保留停滞检测，避免用更长回合掩盖无效策略。

## 2. v0.5 缺陷与对应修复

| 缺陷 | v0.5 原因 | v0.6 修复 | 验证方式 |
| --- | --- | --- | --- |
| 装料时工具竖直 | `load_pose()` 仅旋转 J1，没有末端方向约束；`feed()` 与真实接触无关 | 建立装料板实体、装料预备位和铲料笛卡尔轨迹；工具工作面朝上 | 逐帧测量工作面法向与世界 +Z 夹角；检查工具/材料接触 |
| 带料移动时工作面朝下 | `carry_face_up` 是策略标量，只进入材料公式；自由空间用关节插值 | 删除该动作维；由 `R_world_tool` 实时计算朝上分数；用带方向约束的 SE(3) 轨迹 | 逐帧姿态审计、掉料积分、轨迹回放一致性 |
| 接触前回缩 | 新 `PRECONTACT/ROTATE_TO_WALL` 后又重复旧 `WALL_APPROACH` 序列 | 只保留一条有向状态机；接近段墙距单调不增 | 自动检查阶段序列和工具到墙距离导数 |
| 装料到墙面不是连续物理仿真 | 每刀执行前直接把 `qpos` 放到接近起点 | 整个 episode 保持连续 `qpos/qvel`，所有阶段由同一执行器推进 | 禁止瞬移；检查相邻帧关节位置、速度和时间连续性 |
| 可视化混合真实轨迹与示意插值 | 回放缺失阶段用关节线性插值补帧 | 回放只读取执行器记录的真实帧 | rollout 与在线执行逐位复现测试 |

## 3. 坐标系与姿态定义

新增工具语义坐标系，避免“pitch=0”与真实刀面方向含义不一致：

- `tool_frame`：末端工具刚体坐标系。
- `material_face_normal`：从刀片背面指向承载材料一侧的单位法向。
- `blade_long_axis`：刀片长轴。
- `blade_lateral_axis`：刀片横向轴。
- `tcp_contact`：刀片与墙面接触的几何参考点。
- `feed_contact_site`：与装料材料交互的参考区域。

每个仿真步计算：

```text
face_up_score = dot(R_world_tool * material_face_normal, world_up)
wall_alignment = dot(R_world_tool * material_face_normal, wall_normal_target)
```

装料和稳定搬运阶段要求材料面与水平面的夹角不大于 10°，即 `face_up_score >= cos(10°)`。
考虑数值误差，验收阈值设为：99.5% 的带料非接触帧不超过 10°，所有帧不超过 15°。
近墙旋转阶段允许逐渐失去朝上约束，但必须缩短持续时间，并将此阶段的实际掉料计入材料模型。

## 4. v0.6 全流程状态机

状态只能沿下列有向边转换，不允许回到已经完成的接近状态：

```text
SCAN
  -> DECIDE
  -> MOVE_TO_FEED_PREPOSE
  -> FEED_ALIGN_UP
  -> FEED_DESCEND
  -> FEED_SCOOP
  -> FEED_LIFT_VERTICAL
  -> CARRY_FACE_UP
  -> WALL_ROTATION_PREPOSE
  -> ROTATE_TO_WALL
  -> WALL_STANDOFF
  -> CONTACT_ACQUIRE
  -> WORK_STROKE
  -> SEPARATE_NORMAL
  -> RECOVER_FACE_UP（仍有余料时）
  -> SCAN_RETURN
  -> SCAN
```

关键约束：

- `FEED_ALIGN_UP` 到 `CARRY_FACE_UP`：材料面保持朝上。
- 装料后先沿世界 +Z 抬升到安全高度，再开始水平搬运。
- `WALL_ROTATION_PREPOSE` 位于墙前安全距离；该距离由刀片包络与碰撞检查确定，初始搜索范围 60–100 mm，不写死单一值。
- 只在旋转安全位完成朝墙姿态转换。
- `WALL_STANDOFF -> CONTACT_ACQUIRE`：TCP 到墙面的法向距离单调减小，允许的数值反向误差不超过 0.5 mm。
- 接触成功后才进入 `WORK_STROKE`。
- 有余料时离墙后恢复朝上姿态；没有余料时可以直接返回扫描位。

## 5. 轨迹规划与执行器修改

### 5.1 连续末端轨迹

自由空间运动使用位置插值与四元数 SLERP；在 50–100 Hz 轨迹采样频率下逐点求逆解。每一点检查：

- 关节限位；
- 相邻解支连续性；
- 与墙、装料板、桌面和机械臂自身的碰撞；
- 关节速度与加速度；
- 带料阶段工作面朝上约束；
- 线缆和 D435 支架的保守包络（现阶段使用几何包络，实物线缆仍待 L3 验证）。

禁止回放层自行补关节插值。规划失败的技能必须返回明确原因，由高层重新决策或使用经过验证的投影方案。

### 5.2 连续执行

执行器在一个 episode 内不得重置 `qpos/qvel`。装料、搬运和涂抹共享同一 MuJoCo 状态和仿真时钟。
每个阶段记录实际：

- `qpos/qvel/ctrl`；
- TCP 位姿与工作面法向；
- 工具到墙和装料板的距离；
- 接触力；
- 刀上材料量、掉落量和墙面材料量；
- 当前状态机阶段及转换原因。

### 5.3 材料耦合

`feed()` 不再因为进入 `SCOOP` 状态就直接装料。装料增量需同时满足：

- 工具进入装料材料体积；
- 工作面方向在允许范围；
- 铲入方向与工作面一致；
- 深度、速度和法向力在配置范围内。

运输掉料使用每个 MuJoCo 时间步的真实 `face_up_score`、角速度和线加速度积分。
近墙旋转期间的掉料必须保留，不能因为处于“正确阶段”而免除。

## 6. 策略接口调整

删除动作中的 `carry_face_up`。朝上搬运属于安全且物理必要的底层约束，不应让策略选择是否遵守。

高层策略保留或输出：

- 技能/模式：`DEPOSIT`、`REUSE`、`LEVEL`、`RESCAN`、`FINISH`；
- 刀路起点和终点；
- 刀片平面内方向；
- 接触力；
- 接触开始/结束俯仰；
- 涂抹速度；
- 请求装料量；
- 必要时的曲线偏移。

底层技能负责：装料姿态、朝上搬运、近墙旋转、单调接触、离墙和恢复姿态。训练输入增加实际可观测量：

- 当前刀上材料量；
- 装料板剩余材料量；
- 当前 TCP 位姿和材料面方向；
- 最近一次技能是否规划成功及失败类别；
- 剩余时间预算、回合进度和局部墙面误差摘要。

动作维度变化后，v0.5 策略不得直接继续训练。可以复用网络工具和墙面特征代码，但教师数据、归一化统计与策略检查点全部重新生成。

## 7. 每回合预算与终止条件

当前配置为 `base_steps=6000`、`max_steps=12000`、`max_cycles=80`、`stall_limit=5`。
平均约 34 次循环后结束，确实不足以让策略反复修整 18.5 cm × 18.5 cm 区域。

v0.6 建议配置：

| 参数 | v0.5 | v0.6 建议 | 原因 |
| --- | ---: | ---: | --- |
| `base_steps` | 6,000 | 12,000 | 给基本覆盖和第一轮修整留出约两倍时间 |
| `max_steps` | 12,000 | 24,000 | 允许有效策略继续修整，但设置硬上限 |
| `extension_steps` | 1,000 | 2,000 | 降低频繁触发预算边界的影响 |
| `max_cycles` | 80 | 160 | 支持更多短刀和局部修补 |
| `max_reload_cycles` | 30 | 60 | 与最大循环数同步放宽 |
| `stall_limit` | 5 | 改为滚动窗口 12 | 单次/少量无改善不能过早结束 |
| `min_cycles_before_stall` | 无 | 25 | 未获得基本覆盖前不因早期探索直接退出 |

停滞判断不再只看最后一步。使用最近 12 个决策的联合进展：覆盖率增量、RMSE 下降、P95 下降和有效材料转移。
只有四项均未达到最小进展阈值时才判定停滞。以下条件仍立即终止：达到成功标准、硬步数上限、连续规划失败、
材料耗尽且无法装料，或出现安全约束违例。

注意：这里的 `control_steps` 是 20 Hz 仿真控制步，不等于 PPO 的高层决策步。报告中必须同时记录两者。

## 8. 训练前硬门槛

以下门槛全部通过后才能开始训练：

1. 30 个固定种子的教师完整回合均无瞬移、无碰撞、无非法关节跳变。
2. 装料和带料搬运阶段 99.5% 帧的材料面倾角不超过 10°，任何帧不超过 15°。
3. 30 个回合中装料必须由真实工具—材料接触产生；没有接触时装料增量严格为零。
4. 预接触后的墙面法向距离单调不增；回缩事件为零。
5. 状态机序列不存在重复接近、跳阶段或倒序转换。
6. 材料质量守恒误差小于 `1e-9 m³`。
7. 在线运行轨迹与保存后回放的 `qpos`、材料量和墙面高度场逐位一致。
8. 原生 MuJoCo 窗口人工检查至少 5 个不同种子，确认显示与日志一致。

任何一项失败，只修复环境/规划器并重跑门槛；不得通过调奖励绕过。

## 9. 分阶段训练方案

### P2-A：教师与小规模试训

- 教师示范：200 回合。
- DAgger：4 轮，每轮 40 回合，共 160 回合。
- PPO：50 次更新，每次 2,048 个高层决策，共 102,400 步。
- 验证：固定 60 个降阶/运动学种子，固定 20 个完整 MuJoCo 种子。
- 目的：检查动作分布、终止原因、姿态约束和奖励方向，不以最终性能为目标。

P2-A 只有在以下条件成立时进入正式训练：无结构约束违例；训练回报没有持续发散；至少 95% 的策略动作能被规划器执行或合理投影；
PPO 在覆盖率、RMSE、浪费率中至少两项不劣于 DAgger 教师基线。

### P2-B：正式训练

- 从通过 P2-A 的配置重新使用固定主种子训练。
- PPO：200 次更新 × 2,048 步，共 **409,600 个高层决策步**。
- 每 10 次更新在固定验证集评估；只根据验证集选择检查点。
- 正式测试集：200 个未参与训练/验证的种子。
- 完整 MuJoCo 复测：教师、DAgger、最后 PPO、最佳验证 PPO 各 50 回合。
- 训练失败、崩溃和中间检查点全部保留，不覆盖 P2-A 或 v0.5 记录。

若 409,600 步仍未收敛，先分析失败类别和学习曲线；不自动追加到百万步。只有结构门槛持续满足且曲线仍在改善时，
才提交 P2-C 百万步训练计划。

## 10. 指标与成功标准

最终成功必须同时满足任务质量和物理执行约束：

| 类别 | 指标 | 目标 |
| --- | --- | ---: |
| 墙面效果 | 覆盖率 | ≥ 0.95 |
| 墙面效果 | 厚度 RMSE | ≤ 0.5 mm |
| 墙面效果 | P95 绝对误差 | ≤ 1.0 mm |
| 材料 | 总浪费率 | ≤ 0.20 |
| 材料 | 搬运阶段掉料率 | ≤ 0.05 |
| 姿态 | 带料非接触阶段 >15° 违例 | 0 |
| 轨迹 | 预接触后回缩 | 0 |
| 轨迹 | 碰撞、瞬移、非法关节跳变 | 0 |
| 规划 | 无法执行/投影比例 | ≤ 0.05 |

除均值外报告中位数、P10/P90和95% bootstrap置信区间。PPO只有在物理约束全部满足，且相对教师在主要任务指标上有统计改善时，
才能描述为“优于教师”。

## 13. 建议代码边界

为避免再次把显示逻辑当成控制逻辑，建议拆分：

```text
dummy_loop/wall_cycle/
  frames.py          工具语义坐标系与姿态指标
  skills.py          装料、搬运、旋转、接触、离墙技能
  trajectory.py      SE(3) 插值、IK 连续性、时间参数化
  arm.py             MuJoCo 执行和碰撞/动力学检查
  mortar.py          与真实姿态和接触耦合的材料更新
  env.py             高层决策、奖励、终止条件
  view.py            只消费已记录轨迹，不生成轨迹
```

`view.py` 禁止调用新的 IK、插值或材料更新函数；它只能显示 rollout，确保“看到的就是执行记录”。

## 14. 实施顺序和检查点

1. 整理启动器并建立目录测试；不改变任何算法行为。
2. 建立工具语义坐标系和姿态单元测试。
3. 建立装料板场景与可达位置搜索。

5. 将材料装载/运输改为真实接触与姿态驱动。
6. 修正状态机和回放，完成三个原始问题的回归测试。
7. 跑训练前八项硬门槛并人工检查原生 MuJoCo 回放。
8. 生成全新教师数据，运行 P2-A。

10. 输出结果、失败分析、原生 MuJoCo 脚本、测试日志、配置和提交记录。

每个检查点单独提交。若某一步失败，保留日志并停在该检查点，不提前启动后续训练。
