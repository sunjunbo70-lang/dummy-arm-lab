# 动作空间与观测约定

本文件定义「动作」和「观测」在本项目里的含义。仿真、实机采集、训练、部署共用这一份约定；
改动它等于改动数据格式，必须同时改 `dummy_loop/episode.py` 的字段声明并升级 schema 版本。

当前实现：`dummy_loop/wall/controller.py`（墙面抹涂任务）。M4 统一 Robot API 时以本文件为准收编。

## 坐标系

| 名称 | 定义 | 单位 |
| --- | --- | --- |
| 规范关节坐标 canonical | `canonical = sign × (firmware − zero)`，见 `dummy_loop/__main__.py` jog 路径与 `configs/`。**sign 与 zero 在 M3 标定前未知** | rad |
| V2 模型关节坐标（2026-09-20 起墙面仿真使用） | `q = deg2rad(firmware − HOME)`，HOME = (0,0,90,0,0,0)，正方向与固件相同。这是按 V2 固件资料得到的**候选** canonical（sign 全为 +1、zero = HOME），M3 实测确认后才能写入 `configs/` | rad |
| 世界系 | = 固件基座系：原点在 J1 轴线上，+X 朝前，+Z 向上；模型零位时小臂水平朝前（+X） | m |
| 墙面系 W | 原点在墙面上的工作区参考点；列向量 u 沿墙水平、v 沿墙向上、n 指向墙内 | m |
| 墙面系名义朝向 | n = +X（墙在机械臂正前方），u = +Y，v = +Z | — |
| 刀面系 | x = 刀宽方向，y = 刀面法线（沿 J6 轴外伸），z = x × y。相对 link6：先经安装旋转 `MOUNT_R`（安装系 +Y = link6 +X），再绕 x 转 `blade_tilt_deg` | — |
| TCP | J6 轴线与刀面外表面的交点。刚性抹刀（默认）：距 J6 减速器输出法兰面 `rigid_tool_length()`（抹刀座 + 木柄 + 立柱 + 刀厚），默认夹持使它落在刀面面积形心；弹簧方案：距 J6 裸轴端面 `tool_length`（弹簧未压缩时） | m |

**psi = 0 的约定**：刀宽方向 = −u（与模型零位时 J6 的自然朝向一致，不需要 J6 转 180°）。刀宽仍沿水平方向。

## 动作

每个控制周期一个 4 维增量，表达在**控制器所相信的**墙面系里：

| 分量 | 含义 | 单位 | 每步上限（默认） |
| --- | --- | --- | --- |
| du | 沿墙水平 | m | 0.010（0.2 m/s） |
| dv | 沿墙向上 | m | 0.010 |
| dn | 法向，正 = 压入墙内 | m | 0.004（0.08 m/s） |
| dpsi | 刀面绕法线转角 | rad | 0.05 |

- 控制周期 `dt = 0.05 s`（20 Hz），与参考仿真一致。
- 先限幅再累加到目标位姿；超出上限的部分直接丢弃，不排队。
- 刀面法线始终保持与墙面法线平行，是硬约束，不属于动作。
- **psi 是弱约束**：控制器尽量保持，但可达性优先（原因见 `docs/SIMULATION.md`「腕部奇异」）。实际转角以正解为准。
- 控制器内部维护指令关节角 `q_cmd`，逆解从 `q_cmd` 出发而不是从测量值出发。这与实机位置模式一致：
  跟随误差、下垂、零位误差都不会在这一层被自动吃掉，要靠补偿层显式处理。
- 关节速度默认限 60°/s；超限时本周期只走到限速处（状态 `rate_limited`），目标保留。
- 目标不可达时撤回本次增量（状态 `unreachable`），不把半收敛的解发出去。

### 为什么是末端空间、增量、墙面系

- 末端空间与本体无关，才可能跨平台迁移（见 `docs/research/` 相关讨论）；关节角只对这台臂有意义。
- 增量比绝对位姿对标定误差更宽容：策略学的是「往哪边走多少」，不依赖对墙面绝对位置的精确认知。
- 墙面系让同一个策略对墙放在哪里不敏感；墙面位姿的认知误差由探触标定修正，而不是让策略去学。

## 观测的可得性分级

每个字段必须声明 `availability`，写在 episode 元数据的 `fields` 里：

| 等级 | 含义 | 例子 |
| --- | --- | --- |
| `hardware` | 实机现有硬件就能拿到 | 关节读数、由读数正解的 TCP、控制器目标 |
| `hardware_with_sensor` | 实机需加装传感器才有 | 抹刀座力传感器 `tool_force_N`（刚性工具，默认）；弹簧压缩量 `compression_m`（弹簧方案，仅对比） |
| `privileged` | 只有仿真知道 | 真实接触力、真实 TCP、覆盖图 |
| `command` | 我们自己发出的量 | 动作、关节目标、控制器状态 |

**privileged 字段不得作为策略输入。** 训练代码用 `dummy_loop.episode.hardware_fields(meta)` 取输入字段。
违反这一条的策略在仿真里会表现很好，部署到实机时它依赖的输入根本不存在。

## 时间

逐帧必有 `seq`（无缺号递增）、`t_sample_s`（传感器采样时刻）、`t_host_s`（主机接收时刻）。
实机旧协议拿不到逐轴采样时刻时，`t_sample_s` 写 NaN、元数据 `sample_time_known: false`，
并必须给出实测的 `latency_upper_bound_s`。**不得用主机接收时刻冒充采样时刻。**
这与 `configs/` 的时效契约和 M2 任务卡是同一条要求。
