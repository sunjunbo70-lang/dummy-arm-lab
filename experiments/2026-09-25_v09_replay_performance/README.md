# v0.9 原生回放卡顿修复（软件会话，L1）

根因：np.load压缩NPZ返回惰性NpzFile，不缓存成员。旧循环中的z['wall'][i]每次先解压整段三维数组，再取一帧；同时q/blade/phase也重复读取。墙面长记录为1–2GB解压数据。播放时钟照常推进，阻塞后跳到新的时间索引，造成闪现。

实测5份记录旧单帧wall访问0.309–2.943秒。新实现启动时每个成员仅读取一次，关闭压缩包；占用缓存190–2131MB，实测初始解压0.239–3.000秒（随存储和系统负载变化）。新场景更新中位13.67–19.11ms，P95约14.78–20.08ms。此计时包含采样、正运动学、墙面/刀面/边界几何准备，不包含交互窗口v.sync或显示器刷新，不宣称已测得稳定60FPS。原始数据未改。

记录采样中位间隔0.06秒，旧播放器直接保持上一采样姿态。现在按时间线性插值六关节用于显示，材料仍用原采样值，不对材料或物理结果造中间状态；窗口标注display only。逐帧键仍按原记录时间点，--raw-samples关闭姿态插值。保持真实记录时长，不把渲染变慢当成慢动作。

两个针对性回归测试通过：关闭并删除临时压缩档后缓存仍可采样；中间时刻、边界和重复时间戳插值正确。五份真实记录分别完成30个不同时间点场景更新测试，benchmark.json保存原始性能测量。benchmark.py可复现。

用户操作：关闭旧回放窗口，再双击原launchers/replay/v09_final_*.cmd即可使用新播放器，无需重训或重录。长记录在打开窗口前需要一次性加载，终端显示提示；五窗口同时开会增加内存占用。

回退可从git恢复dummy_loop/wall_cycle_v09/replay.py旧版本；不改变任何仿真记录、模型权重或硬件控制。
