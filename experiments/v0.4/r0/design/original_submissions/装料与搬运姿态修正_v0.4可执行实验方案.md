# 整片连续强化学习 v0.4：装料/搬运姿态修正 —— 可执行实验方案

状态：**方案稿，待审，仓库代码未做任何改动**。证据等级 L1。本文档取代上一版设计稿（`装料与搬运姿态修正方案_v0.4设计稿.md`）里"新工具几何本轮暂不合并"的建议——按你的最新指示，`models/tools/lab_20260922.json`（`实测末端工具仿真.cmd` 对应的模型）现在作为几何标准，从这一版开始就用。

## 零、你三条回复带来的三处具体改动

1. **"朝天"部分可行即可接受** → 在阶段 A 的可达性扫描里，直接按 full / partial / none 三级输出百分比，不设"必须全可达"的硬性门槛，训练阶段用扫描结果自动决定每个工位实际能给多陡的 carry_tilt（见阶段 C）。
2. **墙（木/砖）比工具（光滑金属）粘料能力强** → 这是一个具体、可以直接编码的物理不对称性，且现有模型里**明确缺失**（`mortar.py` 第 59 行原话把"substrate 之间粘附力不同"列进"NOT MODELLED"）。具体改法见下面 3.2：把 `lift_wall_fraction`（刀离墙时，料在墙/刀之间怎么分）从现在对称的 0.5 提到一个偏向墙面的值，先设 0.75（估计值，非实测，见验证计划里的敏感性分析）。
3. **现在没法用实体验证，只能先靠仿真+文献** → 材料参数继续用水泥砂浆的文献量级（Banfill 2003：屈服应力 100–500 Pa、塑性粘度 1–3 Pa·s，现在用的 τ_y=250 Pa、μ_p=2 Pa·s 就落在这个区间中段），不额外编造精确数字；报告里持续标注"L1，文献量级，非实测"。你提到"实际施工水泥用得最多"，这正好和现在的取值方向一致，不用改基准值，但要在阶段 D 的参数敏感性里把 τ_y 从 100 扫到 1000 Pa（沿用 v0.3 `mortar_sweep.py` 已经做过的范围），确认结论对"水泥砂浆的典型区间"稳健，不是踩在某个特定数值上才成立。

## 一、这一版的范围变化：新工具几何现在是标准，不再延后

`lab_20260922` 相比旧几何（`wall_cycle` 现在用的）的关键差异，直接决定了阶段 A 必须先做：

| 项 | 旧几何（v0.3 用） | 新几何（`lab_20260922`，本次标准） | 影响 |
|---|---|---|---|
| 法兰到接触面 | 约 40 mm | **70.5 mm**（TCP 外移 40.5 mm） | 力臂变长，J5/J6 力矩负担按比例增加；旧作业区、旧可达表全部失效 |
| J6 可用力矩上限 | 候选 0.07 N·m（直驱估计） | **候选 0.9 N·m 连续值**（MINIF08-30，减速比 30:1，厂商未confirm，效率/转速曲线未辨识） | 力矩预算变化方向不确定（虽然峰值数字变大，但连续输出能力和效率未知，不能直接当作"更好转"） |
| 刀片几何 | 参考模型占位尺寸 | **实测标注**：124 mm 长，尾宽 42 / 尖部肩宽 35 mm | 直接改变 `mortar.py` 里 `blade_polygon`/`blade_shape` 的网格范围和体积计算 |
| 质量分布 | 参考模型占位 | 刀 80g / 减速器 150g / 转接板 20g / 夹具 35g（**均为估计，未称重**） | 影响联合仿真里的惯量，间接影响伺服跟踪误差 |

`env.py`/`arm.py` 现在用 `CycleConfig` 里的散装字段（`scene_wall_distance_m` 等）拼一个 `SceneConfig`（`arm.py` 的 `scene_config(cfg)` 函数），并不读 `lab_tool.py` 的 profile。**必须先把这条路打通**，否则后面的训练用的仍是旧几何的影子。

## 二、阶段 A：新几何下的可达性与作业区重算（阻塞后续所有阶段）

### A1. 打通配置路径
- `dummy_loop/wall_cycle/config.py`：`CycleConfig` 新增 `tool_profile: str = 'legacy'` 字段；为 `'lab_20260922'` 时，`arm.py::scene_config(cfg)` 改为调用 `lab_tool.scene_config(wall_distance=..., wall_lateral=..., wall_center_z=...)`，用 profile 里的刀具/减速器/J6 力矩参数覆盖散装字段，而不是重新拼一份。
- 保留 `tool_profile='legacy'` 默认值，`replay.py`（已经 pin 死 `physics='v0.2'`）不受影响。

### A2. 可达性 + carry_tilt 三态扫描
扩展 `tools/simulation/v2_trowel_reach.py`（或新开 `tools/simulation/lab_tool_reach.py`，避免和旧脚本的既有回归测试耦合）：
- 输入：候选墙距网格（沿用 v0.3 用过的 0.28–0.38 m）、work_points 网格（沿用现有 18.5×18.5cm 区域候选，先不假设还成立）。
- 对每个候选工位，额外测试三个 `carry_tilt`（0°=朝天，45°，90°=现状贴墙朝向）能否各自求出可行 IK 解（复用 `arm.py` 里 `_solve_seeded`/`_step` 的碰撞与关节限位检查逻辑）。
- 输出分级：`full`（三态都行）/ `partial`（只有 45°/90° 行，或部分角度行）/ `none`（连 90° 现状都难，說明这个工位本来就有问题，不是这次改动引入的）。
- **产出**：`experiments/00_initial_debug/records/2026-09-22_lab_tool_reach/`（新目录，不覆盖已有的 `2026-09-22_lab_tool`），含 `reach_carry.json` + 一张"工位 × carry_tilt 可行等级"热力图（复用 `plot_wall_study.py` 的绘图方式）。

### A3. 重算作业区
按你最初的规则（最大内切圆正方形 × 80% 冗余）在新几何 + 新可达表上重算，产出新的 `work_area.json` 变体（新文件名，如 `work_area.lab_20260922.json`，不覆盖 v0.3 的 `work_area.json`）。

**验收标准**：给出 A2 的 full/partial/none 三级占比数字（例如"62% 工位可以完全朝天取料，31% 只能到约 45°，7% 连现状贴墙朝向都难以覆盖，判定为工位本身不可用"这种具体表述），以及新作业区的尺寸——这两项是后面所有训练是否值得投入的前提，必须先看到数字再决定是否继续。

## 三、阶段 B：材料物理扩展

### B1. 料台取料物理化
新增 `FeedBoardModel`（可以放在 `mortar.py` 里新增一个函数集合，复用现有 `MortarParams`/`squeeze_support`/`extrude`，不新开一套参数系统）：
- 料台建模成一层固定厚度（假设 15 mm，可调）、固定屈服应力的水平供料层，屈服应力沿用墙面同一批文献值（见零、第 3 条）。
- 取料时的"重力方向"改成沿刀面法向（垂直压向料台），压力分量随 `carry_tilt` 变化：`g_n_feed = cos(carry_tilt)`（0°朝天时法向分量最大，取料效率最高；90°贴墙朝向时法向分量趋近 0，取料效率趋近于只能靠刀边蹭一点）。
- 接口：`feed(carry_tilt, dwell_s) -> loaded_m3`，替换 `env.py` 第 293-295 行的 `material.load_random(ml)`。

### B2. 搬运段连续物理
- `CARRY`/`APPROACH` 两段插入固定数量采样点（建议 8–10 个，和现有 `stroke_samples` 量级一致，不需要更密），`carry_tilt(t)` 按预设或策略输出的插值曲线（阶段 C 定义），每个采样点调用一次 `mortar.air(carry_tilt(t), stats)`，替换掉现在 `arm.py` 第 281 行"只在终点调用一次、且角度用错"的写法。
- 这一步不要求真正跑 MuJoCo 逐步动力学（那是 `execute()` 贴墙段才做的事），运动学插值 + `air()` 逐步扣料就足够解决"中途掉料完全不计入训练信号"这个核心问题，避免把工程量抬高到要给搬运轨迹也做力控联合仿真。

### B3. 墙-刀不对称粘附（你提出的物理点）
- `MortarParams.lift_wall_fraction`：0.5 → **0.75**（`mortar.py` 第 74 行的默认值，`end_stroke()` 里 `share = f * B[r,cc] / len(keys)`，`f` 越大离墙时留在墙上的比例越高）。这个改动**只有一行**，但要在阶段 D 做敏感性扫描（0.5 / 0.65 / 0.75 / 0.85 四档），因为这是本方案里"估计值"中主观性最强的一个，需要看结果对它敏不敏感，而不是拍一个数字就定下来。
- 同时在 `mortar.py` 顶部的模块说明里把"NOT MODELLED: adhesion strength different from cohesion"这条改成"partially modelled via asymmetric lift_wall_fraction; still not a true two-surface adhesion model"，如实标注这是简化，不是完整方案（真正的双面粘附模型需要分别给墙、刀各自一个粘附系数，工作量明显更大，这次先用一个偏移参数近似）。

## 四、阶段 C：姿态序列、教师与奖励

### C1. 姿态序列（延续上一版设计，结合 A2 的分级结果）
```
LOAD(carry_tilt=该工位A2分级允许的最大值)
  → CARRY(carry_tilt 尽量维持在 LOAD 时的值，随时间小幅衰减，见下)
  → APPROACH(carry_tilt 从当前值线性过渡到 pitch_start，只在离墙最后 ~[stand_off, 0] 这一段完成)
  → CONTACT(不变)
  → LIFT(若 blade_volume_m3 仍 > 阈值，carry_tilt 回到该工位允许的最大朝天值；否则回到 0，即直接回料台)
```
`carry_tilt` 的"该工位允许的最大值"直接读 A2 的分级结果（full→0°，partial→扫描给出的具体可行角度，none→当前 90°，即完全不变，这部分工位这次方案不影响）。

### C2. 教师改写
`teacher.py` 按 C1 序列直接写规程化动作（不是训练出来的，是像"贴墙先立起"最初那样直接来自操作经验）。新增一组对照教师：
- `carry_face_down`（现状，等同于恒定 90°，做对照基线）
- `carry_face_up`（按 C1 新规程）

### C3. 指标与奖励
- 新增 `carry_loss_m3`（B2 里 `air()` 逐采样点累计的 dropped，独立于贴墙阶段 `waste`）。
- `env.py` 的 `_get_obs`/reward 里加一项 `-carry_loss_m3 * loss_weight`（`loss_weight` 建议先等同于贴墙浪费的权重，不单独调，减少一次超参搜索）。
- 报表（`wall_cycle_report.py`）新增 `carry_loss_m3` 单列，不与 `waste` 合并展示。

## 五、阶段 D：训练与对照实验

延用 v0.3 的方法论——同一套其余参数，只改被测自由度：

| 分组 | 预热教师 | 其余参数 | 目的 |
|---|---|---|---|
| 对照组 | `carry_face_down`（现状） | 与 v0.3 technique_teacher 一致 | 复现"改之前"的基线，同一套代码框架下重跑，确保对照公平（不是直接拿 v0.3 旧数字比较，那是在旧几何下跑的） |
| 实验组 | `carry_face_up`（新规程） | 同上 | 验证新规程是否显著降低 `carry_loss_m3`，是否连带改善整体覆盖率/浪费 |

流程：教师 120 局 → 行为克隆 → 3 轮 DAgger → PPO 60×1024（先复用 v0.3 的训练量，不急着加大，见下面时间估算）。

**在跑完整 PPO 之前，先做两个便宜的中间检查点（都不需要机械臂运动学，几十分钟内出结果）**：
1. **物理扫参**（B1+B3 做完即可跑，不依赖 C/D 的任何 RL 代码）：固定 carry_tilt ∈ {0°,30°,60°,90°} × lift_wall_fraction ∈ {0.5,0.65,0.75,0.85}，只测取料/搬运/离墙这条链路的 `carry_loss_m3`，产出类似 `mortar_sweep.json` 的表。**这是回答"物理本身是否支持你的判断"最快的一步，应该最先跑。**
2. **教师对照**（C2 做完即可跑，不需要训练）：`carry_face_down` vs `carry_face_up` 两个教师各跑 100 局，只看 `carry_loss_m3` 和 `覆盖率/浪费`，不涉及任何 PPO。如果这一步两组教师的 `carry_loss_m3` 差距不明显，说明 A2 的可达性限制（partial 工位太多）或 B1/B3 的参数设定可能有问题，要在投入完整训练前先排查。
